# Plan — Project Scaffolding (Phase 0)

## 1. Scaffold the Svelte + Vite + TypeScript project

1. Run Vite's scaffolding for a Svelte + TypeScript project at the repo
   root (`npm create vite@latest . -- --template svelte-ts`, or equivalent
   manual setup if the interactive scaffold doesn't fit into a non-empty
   directory cleanly).
2. Install dependencies with `npm install`.
3. Confirm `npm run dev` starts a local dev server and the default Vite
   starter page loads in the browser.
4. Confirm `npm run build` produces a `dist/` output without errors.

## 2. Add linting and formatting

1. Add ESLint with the TypeScript + Svelte plugins
   (`eslint`, `typescript-eslint`, `eslint-plugin-svelte`) using a minimal
   recommended config.
2. Add Prettier, including `prettier-plugin-svelte` so `.svelte` files
   format correctly, plus `eslint-config-prettier` to avoid rule clashes
   between ESLint and Prettier.
3. Add `npm run lint` (ESLint check) and `npm run format` (Prettier write)
   scripts to `package.json`.
4. Run both against the freshly scaffolded project and fix any reported
   issues so the project starts from a clean baseline.

## 3. Replace the starter page with the quids-in placeholder

1. Replace the default Vite/Svelte starter markup in the root component
   with a minimal placeholder: the supplied custom quids-in logo and a
   short line of text noting the app is under construction.
2. Remove unused starter assets/boilerplate (default Vite/Svelte logos,
   counter demo, etc.) that came from the scaffold template.
3. Add responsive styling so the logo and text remain readable on phone,
   tablet, and desktop viewport widths.
4. Confirm the placeholder renders correctly via `npm run dev`.

## 4. Add the placeholder season data file

1. Create `data/season-2025-26.json` containing:
   - 12 dummy participants, each with a `name` and `teamName` field.
   - An empty (or absent) Gameweek results array, per the array-based
     structure agreed for Gameweek data (latest Gameweek = last array
     entry, to be used starting Phase 2).
2. Keep the shape intentionally simple and easy to extend in Phase 1
   onwards — this phase only needs the file to exist with a sensible
   shape; the app does not read it yet.

## 5. Tidy up and document

1. Ensure `.gitignore` covers `node_modules/`, `dist/`, and other
   Vite/editor artefacts (already partially in place — confirm nothing
   generated by the scaffold is missed).
2. Add a short root `README.md` (or extend if one now exists from the
   scaffold) with: how to install (`npm install`), how to run locally
   (`npm run dev`), how to lint/format.
3. Review the diff as a whole for anything scaffold-generated that isn't
   needed (sample tests, extra config files) and remove it.

## 6. Verify against [validation.md](./validation.md)

1. Work through each check in `validation.md`.
2. Fix anything that doesn't pass before considering Phase 0 complete.
